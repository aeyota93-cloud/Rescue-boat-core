# Три сервера: выбор вручную и «Сравнить пути» по всем дорогам — договор (v1, 2026-10-13)

Макет согласован с пользователем 13.10 (три экрана): «Сравнить пути» меряет все дороги и
одной кнопкой пускает через лучшую; в «Туннеле» у «Через VPN» подменю «Авто / Основной /
Запасной 1 / Запасной 2»; в «Подписках и серверах» режим «Авто: основной → запасной 1 →
запасной 2» или «Всегда <сервер>». Новых списков в «Туннеле» НЕТ.

Подписка (PasarGuard) отдаёт три сервера: «NL» (VLESS Reality TCP), «NL запасной» (VLESS
XHTTP, приходит через `rescue-links`, см. `failover.md`), «NL игры» (Hysteria2, UDP/QUIC).

## Серверы и их имена в интерфейсе

- Серверы = выходы из `select` в порядке подписки, без групп (`lowest`, `balance`, …) —
  тот же список, что у сторожа (`failoverServers` в `v2/rescuestats/failover.go`).
- Имена в интерфейсе — по порядку, НЕ по remark: первый — «Основной», дальше «Запасной 1»,
  «Запасной 2», … Под именем — подсказка по типу выхода: `hysteria2` (и `tuic`) — «для игр
  и звонков»; остальные запасные — «если основной заблокируют». Настоящее имя (remark)
  показывать мелко рядом, как сейчас.
- Ключ сервера для файлов: `key = первые 12 символов hex(sha256(UTF-8 тега))`, строчные.
  Приложение и ядро считают одинаково (тест на общий пример: тег `NL запасной`).

## Выбор сервера для программы/сайта (раздельный туннель)

Файлы в `split-tunnel-dir` (как `via-vpn.json`, тот же формат sing-box source rule-set):

- `via-server-<key>.json` — пункты, закреплённые за сервером с этим ключом.

Ядро (`v2/config/split_tunnel.go`), при сборке конфига:

- для КАЖДОГО сервера из `select` — локальный набор `rescue-via-server-<key>` (файл нет —
  создать пустой, как сейчас) и правило `rule_set: rescue-via-server-<key>` → `route` на
  выход с этим тегом;
- эти правила стоят ПЕРЕД правилом «через VPN» (`rescue-via-vpn`);
- файлы серверов, которых нет в профиле, ядро не трогает и не читает.

Приложение:

- `split-tunnel.json` получает поле `servers: {"<тег>": <SplitList>}` (нет поля — пусто;
  старый файл читается).
- Пункт может быть только в одном месте: «мимо VPN», «через VPN (Авто)» или за одним сервером.
- `via-vpn.json` = «через VPN (Авто)» ∪ ВСЕ пункты, закреплённые за серверами;
  `via-domains.json` — то же для доменов (DNS как у VPN). Так при пропаже сервера из
  подписки его пункты честно идут через «Авто», а не мимо VPN.
- В меню строки (Туннель, Сейчас в сети): «Через VPN ▸ Авто (основной, при сбое — запасные)
  / Основной / Запасной 1 / …» с галочкой у текущего; «Мимо VPN»; «Сравнить пути…»;
  «Убрать из списков». Если в профиле один сервер — подменю нет, как сейчас.
- В строке списка рядом с пунктом: «через запасной 2» (или «через основной»); у пункта,
  чей сервер пропал из подписки: «сервера нет — идёт через Авто».
- «Сейчас в сети»: столбец «Путь» показывает сервер, через который реально идёт соединение
  (последний элемент цепочки соединения из clash API), именем из интерфейса.
- Списки по-прежнему меняются на лету (sing-box перечитывает файлы).

## Режим «для всего остального» (Подписки и серверы)

- Радио-список вместо карточки «Запасной»: «Авто: основной → запасной 1 → …» (= опция
  `rescue-failover` включена) и «Всегда <имя>» для каждого сервера (= `rescue-failover`
  выключена + выбор этого выхода в `select` через существующий выбор прокси clash API).
  Выбор сохраняется между запусками; смена режима не требует переподключения (кроме
  включения/выключения сторожа — тогда переподключение, как сейчас у переключателя).
- В строке «Авто» — «сейчас: <имя> · отвечают N из M»; у каждого сервера — пинг.
- Один сервер в профиле — нынешняя честная заглушка.
- Главная: «работаем через запасной 1/2» (имя по порядку).

## «Сравнить пути» v2 (дополнение к `compare-paths.md`)

Запрос не меняется. Ответ — новое поле `paths.servers` (поле `vpn` остаётся: текущий выбор
`select`, для старых версий приложения):

```json
"paths": {
  "direct": {...},
  "vpn": {...},
  "servers": [
    {"tag": "NL", "available": true, "first_ms": 380, "samples": [95, 97], "note": "", "estimate": false},
    {"tag": "NL запасной", ...},
    {"tag": "NL игры", ...}
  ]
}
```

- `servers` — в порядке `select`, без групп; каждый меряется ЧЕРЕЗ СВОЙ выход по тегу
  (не через `select`). Методы те же: `tls` — как у `vpn`; `icmp` — `estimate:true`, в
  `samples` качество туннеля этого сервера (connection-test-url через этот выход), `note`
  как у `vpn`.
- Дороги меряются по кругу (direct, vpn, сервер 1, сервер 2, …), пауза ~300 мс, чтобы
  колебания сети задевали всех одинаково. Ответ перезаписывается по ходу, как сейчас.
- `count` по умолчанию остаётся 10.

Приложение:

- Таблица: «Напрямую», затем серверы по именам из интерфейса (строку `vpn` не показывать,
  если есть `servers`; пометка «сейчас» — у дороги, которой цель идёт сейчас).
- Лучшая дорога — правило из `compare-paths.md` («хуже», если неудач больше на ≥ 10 п.п.,
  иначе медиана; разница < 15 % или < 10 мс — «одинаково»), применённое ко всем; если
  лидеров несколько «одинаково» — лучшей считается текущая (не дёргаем без пользы).
- Кнопки: «Пустить через «<имя>»» (за сервером), «Пустить напрямую» (в «мимо VPN»),
  «Оставить как есть». При `estimate` у серверов — вывод с оговоркой: «для игры точно
  покажет только сама игра; по качеству дороги лучше всего — <имя>», кнопка остаётся.

## Тексты

Только по-русски, стиль «Д». Протоколы (VLESS, XHTTP, Hysteria2) в основном интерфейсе не
показывать — только в подсказке «подробнее» на странице серверов.
