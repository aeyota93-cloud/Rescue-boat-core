# «Сравнить пути» — договор ядра и приложения (v1, 2026-10-11)

Пользователь выбирает сайт, программу или адрес → за 10–20 с видит, какая дорога лучше:
напрямую или через VPN. Обмен — файлами в папке (как `rescue-stats-dir`), без gRPC.

## Опция ядра

`HiddifyOptions.RescueCompareDir string` — JSON `rescue-compare-dir`, omitempty.
Приложение передаёт её всегда на Windows/desktop (не зависит от «Собирать ошибки»):
`<baseDir>/compare`. Пусто — функция выключена, ядро ничего не делает.

## Запрос (пишет приложение)

`<dir>/req-<id>.json`, запись атомарная (temp + rename). `id` — `[a-z0-9]{8,32}`.

```json
{"v":1,"id":"k3j9x0a1","target":"www.example.com","port":443,"count":10,"created":1791640000000}
```

- `target` — домен, IPv4 или IPv6 (без схемы и пути; приложение нормализует).
- `port` — необязательно, по умолчанию 443.
- `count` — число замеров на каждую дорогу, 3..30, по умолчанию 10.

## Ответ (пишет ядро)

`<dir>/res-<id>.json`, атомарно, ПЕРЕЗАПИСЫВАЕТСЯ по ходу замеров (`done:false`),
последний раз — `done:true`. Приложение читает его раз в 500 мс.

```json
{
  "v": 1, "id": "k3j9x0a1", "target": "www.example.com", "ip": "93.184.216.34",
  "method": "tls",
  "done": true, "started": 1791640000100, "finished": 1791640012000,
  "error": "",
  "paths": {
    "direct": {"available": true, "first_ms": 120, "samples": [41, 40, null, 43], "note": ""},
    "vpn":    {"available": true, "first_ms": 380, "samples": [95, 97, 96, 99], "note": ""}
  }
}
```

- `method`:
  - `tls` — цель отвечает по TCP на `port`: `first_ms` — время от начала соединения до
    завершённого TLS-рукопожатия на НОВОМ соединении (SNI = домен, для IP — без SNI;
    сертификат не проверяем — меряем время, не доверие). `samples` — задержка запрос→ответ
    на уже открытом соединении (HTTP/1.1 `HEAD /` с keep-alive; если сервер закрыл —
    переподключиться, это не неудача). Если TLS не вышел, но TCP открыт — допустимо
    мерить запрос→ответ любым коротким обменом, иначе `samples` = время TCP-соединения
    напрямую и `available:false` для VPN с `note`.
  - `icmp` — TCP на `port` не отвечает (например, игровой сервер только по UDP):
    `direct.samples` — ICMP ping (ядро rb.12+ умеет ICMP через прямой выход);
    `vpn.available:false`, `vpn.note:"через VPN измерить нельзя: сервер отвечает только
    на игровые пакеты"`, а в `vpn.samples` — для оценки — замеры качества туннеля
    (connection-test-url через VPN), `vpn.estimate:true`.
- `samples` — миллисекунды, `null` = неудача (таймаут 2 с на замер). Пауза между замерами
  ~300 мс. Дороги меряются ПООЧЕРЁДНО (direct, vpn, direct, …), чтобы волны сети
  влияли на обе одинаково.
- Дороги: `direct` — прямой выход (как в quality-пробах), `vpn` — выход VPN
  (select/default, как в quality-пробах). Правила маршрутизации НЕ участвуют: меряем
  конкретный выход.
- `error` — непустой, если запрос не выполнить целиком (не резолвится домен, неверный
  запрос, ядро остановлено); тогда `done:true`.
- DNS для `direct` — через прямой DNS, для `vpn` — пусть резолвит сам выход (домен
  передаётся как есть). `ip` — адрес, полученный прямым DNS (для показа).

## Жизненный цикл

- Ядро сканирует `<dir>` раз в 1 с, пока работает; берёт `req-*.json` без `res-*.json`;
  одновременно не больше 1 замера (остальные ждут). Повреждённый запрос → `res` с `error`.
- Приложение удаляет `req-`/`res-` своего `id` после показа результата. Ядро при старте
  удаляет файлы старше 1 часа.
- Лимит: не больше 30 запросов в очереди, лишние — `error:"слишком много запросов"`.

## Вывод (считает приложение)

- Медиана `samples` (без `null`), разброс = средн. |Δ| соседних, неудачи = доля `null`.
- Дорога «хуже», если неудач больше на ≥10 п.п., иначе сравниваем медианы: разница
  < 15 % или < 10 мс — «одинаково», иначе меньшая медиана лучше.
- При `estimate:true` вывод не делается: «для игр по UDP сравнить нельзя; прямой путь: …».
