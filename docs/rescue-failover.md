# Автопереключение «основной → запасной» — договор ядра и приложения (v1, 2026-10-11)

Подписка PasarGuard отдаёт два сервера: «NL» (VLESS+Reality, основной) и «NL запасной»
(VLESS+XHTTP+Reality), см. `vpn-server/docs/xhttp-backup.md`. Встроенные группы sing-box/Hiddify
(urltest, balancer «lowest-delay») выбирают самый быстрый — это НЕ то, что нужно: основной
должен работать всегда, пока жив. Поэтому — свой «сторож» в ядре.

## Опция ядра

`HiddifyOptions.RescueFailover bool` — JSON `rescue-failover`, omitempty. Приложение передаёт
`true`, когда в профиле ≥ 2 серверов и пользователь не выключил автопереключение (по умолчанию
включено). Выбор сервера вручную в приложении автопереключение НЕ отключает автоматически —
это отдельный переключатель (см. «Приложение»).

## Сторож (ядро)

- Порядок серверов — порядок тегов в выходе `select` (как их строит `builder.go`: порядок из
  подписки; у PasarGuard — по `priority` хоста, основной первым). Основной = первый тег,
  запасные = остальные по порядку.
- Каждые 30 с проверяет ОСНОВНОЙ: `urltest` к `connection-test-url` через этот выход
  (как probe.go), таймаут 5 с. Пока активен запасной — проверяет и основной, и активный.
- Переключение на следующий живой запасной: 3 неудачи основного подряд (≈ 1,5 мин).
  Возврат на основной: 3 удачи основного подряд. «Живой» запасной — его последняя проверка
  удачна; если живых нет — остаёмся на основном (ничего не дёргаем).
- Переключение — `selector.SelectOutbound(tag)` у выхода `select` (тот же путь, что ручной
  выбор через clash API), существующие соединения рвутся (`interrupt`), чтобы приложения
  переподключились.
- Если `select` уже указывает НЕ на основной и не на выбранный сторожем запасной (пользователь
  выбрал вручную при выключенной опции, а потом включил) — сторож начинает с основного.
- Событие переключения пишется строкой в `<rescue-stats-dir>/errors-YYYYMMDD.jsonl` (если папка
  задана): `{"v":1,"t":…,"kind":"failover","route":"vpn","host":"<новый тег>","msg":"основной
  не отвечает 3 раза подряд"|"основной снова отвечает"}`. Приложение показывает это в Ошибках
  как отдельный вид «переключение».
- Без опции или при одном сервере сторож не запускается.

## Приложение

- Опция: `rescueFailover` в `singbox_config_option.dart`; в `config_option_repository.dart`
  передавать `true`, если настройка «Переключаться на запасной автоматически» включена
  (новая преференция, по умолчанию true). Число серверов ядро проверит само.
- «Подписки и серверы»: карточка «Запасной» вместо заглушки:
  - если в профиле один сервер — текущая честная заглушка («Пока запасного нет…» +
    «Добавить подписку»);
  - если ≥ 2 — «Запасной: <имя второго сервера>», состояние «готов» / «используется сейчас»
    (активный выход `select` — из `activeProxyNotifierProvider`), пинг; переключатель
    «Переключаться автоматически» (RescueToggle).
- Главная: под «СЕРВЕР» при активном запасном — пометка «работаем через запасной».
- Ошибки: вид `failover` — «переключение на запасной» / «возврат на основной».
- Тексты только по-русски, стиль «Д».
