Макеты: холст «Шлюпка спасения — дизайн», вариант Г (тёмный). Этот файл — единственный
источник правды для агентов A–D2. Меняется только через владельца (основная сессия).

## Решения пользователя

- Только тёмная тема. Только русский язык в новых экранах (строки прямо в коде, без slang).
- Никакого трафика по программам/сайтам на экранах. Расход подписки (одна цифра) — можно.
- Подсказки не генерируем. Показываем факты: список ошибок, счётчики, здоровье.
- Фоновые замеры качества: пинг, джиттер, потери, обрывы, «замирания». «Сравнить пути» — позже.
- Трей: обычное меню значка (статус, оценка, число ошибок за час, «Открыть», «Выйти»).
- Меню: Обзор · Раздельный туннель · Ошибки · Подписки и серверы · Настройки.
  Убрать из навигации: Профили, Прокси, Общие настройки, WARP (код не удалять).
  «Для опытных» (внутри Настроек): Журнал, Маршрутизация (с «Правилами маршрутов»), DNS,
  Подключение. «Обход блокировок» (TLS tricks) — обычный блок наших Настроек.
- Шрифт: системный Segoe UI (Windows), ничего не скачиваем и не вшиваем.

## 1. Папка статистики (ядро ↔ приложение)

- HiddifyOptions: `"rescue-stats-dir": "<путь>"` (Go: `RescueStatsDir string json:"rescue-stats-dir"`).
  Пусто — ядро ничего не пишет и не замеряет. Приложение передаёт `<baseDir>/stats` на
  Windows, если в настройках включён сбор (по умолчанию включён).
- Формат: JSON Lines, UTF-8, одна запись — одна строка, только дописывание. Файлы по
  местной дате: `errors-YYYYMMDD.jsonl`, `quality-YYYYMMDD.jsonl`.
- Ядро удаляет `errors-*` старше 7 дней и `quality-*` старше 30 дней (при старте и раз в сутки).
- Последняя строка может быть недописанной: читатель пропускает строки, которые не парсятся.
- Поле `v` — версия формата записи (сейчас 1). Неизвестные поля читатель игнорирует.
- Ограничение: не больше 5000 записей ошибок в сутки; сверх — одна строка
  `{"v":1,"t":…,"kind":"suppressed","n":<сколько пропущено>}` при смене суток или остановке.

### errors-YYYYMMDD.jsonl — неудачные соединения

```json
{"v":1,"t":1760030463000,"kind":"reset","app":"chrome.exe","host":"kinopoisk.ru",
 "ip":"213.180.204.211","port":443,"net":"tcp","route":"vpn","dur_ms":850,"n":1,
 "msg":"read: connection reset by peer"}
```

| Поле | Тип | Смысл |
|---|---|---|
| t | int | время, unix миллисекунды |
| kind | string | `timeout` · `reset` · `refused` · `dns` · `tls` · `eof` · `stall` · `other` · `suppressed` |
| app | string | имя exe (без пути), `""` если неизвестно |
| host | string | домен, если известен, иначе `""` |
| ip, port, net | string, int, string | адрес назначения; net = `tcp`/`udp` |
| route | string | `vpn` · `direct` · `block` (по итоговому outbound) |
| dur_ms | int | сколько жило соединение до ошибки (0 — не установилось) |
| gap_ms | int | только для `stall`: длина «замирания» |
| n | int | сколько одинаковых событий схлопнуто (одинаковые kind+app+host+route в пределах 1 с) |
| msg | string | исходный текст ошибки, до 300 символов, без секретов |

Что считается ошибкой: неудачный dial у outbound; соединение закрыто с ошибкой; неудачный
DNS-запрос программы. Не считается: нормальное закрытие (EOF после данных), отмена самой
программой, собственные замеры ядра. `stall`: UDP-соединение, которое получало данные,
затем ≥1500 мс не получало ничего, хотя программа продолжала отправлять.

Сопоставление ошибок Go: deadline/timeout → `timeout`; connection reset → `reset`;
refused → `refused`; no such host / NXDOMAIN / ошибки DNS → `dns`; TLS/Reality handshake →
`tls`; EOF/unexpected EOF до первых данных → `eof`; остальное → `other`.

### quality-YYYYMMDD.jsonl — замеры раз в 60 секунд

```json
{"v":1,"t":1760030460000,"type":"probe","path":"vpn","samples":[48,51,null,47,49]}
{"v":1,"t":1760030460000,"type":"probe","path":"direct","samples":[12,11,13,12,12]}
{"v":1,"t":1760030460000,"type":"counters","conns":143,"errs":3,"dns_ok":88,"dns_fail":0}
```

- `probe`: 5 HTTP-запросов к `connection-test-url` подряд, через выбранный VPN-outbound
  (`path:"vpn"`) и через direct (`path:"direct"`). `samples` — задержки в мс, `null` = потеря
  (таймаут 3 с). Замер только пока ядро запущено; трафик замеров в errors не попадает.
- `counters`: за прошедшую минуту — сколько соединений открыто, сколько закончилось ошибкой,
  сколько DNS-запросов успешно/неуспешно.

|---|---|---|

### Формула оценки (0–100)

Окно — 24 часа, по минутам (одна минута = одна пара probe + counters).
- Пинг (медиана vpn): ≤80 мс → 100; 80–150 → линейно до 70; 150–300 → до 40; >300 → 20.
- Джиттер (ст. отклонение vpn-выборок): ≤10 мс → 100; ≥60 мс → 40; между — линейно.
- Потери (доля null среди vpn-выборок): 0 % → 100; ≥10 % → 0; между — линейно.
- Стабильность = среднее(джиттер, потери) — так строка и называется на экране.
- Соединения без ошибок: 100 × (1 − errs/conns), при conns = 0 → 100.
- DNS: 100 × dns_ok/(dns_ok+dns_fail), при нуле запросов → 100.
- Общая = 0.25·пинг + 0.15·джиттер + 0.20·потери + 0.25·ошибки + 0.15·DNS, округлить.
- Полоски «хорошо/средне/плохо» = доли минут окна с оценкой ≥85 / 60–84 / <60.
- Подпись под строкой — факт, а не совет: «48 мс, обычно 45–60», «3% соединений с ошибкой».
- Нет данных (сбор выключен, ядро не запущено) — `HealthSnapshot.empty`, экраны пишут
  «Нет данных: замеры идут, пока VPN включён».
