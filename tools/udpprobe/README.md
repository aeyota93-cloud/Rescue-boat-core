# Проверка UDP через выходы

Утилита запускает отдельный sing-box и проверяет каждый выход, кроме групп,
`direct`, `block` и `dns`. Для каждого выхода UDP-проба и HTTP urltest идут
параллельно с общим сроком 4 секунды. Все выходы проверяются параллельно.

Запустите из корня репозитория в PowerShell:

```powershell
$env:GOTOOLCHAIN = 'go1.25.6'
$env:CGO_ENABLED = '0'
go run -ldflags=-checklinkname=0 -tags with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api,with_grpc,with_awg,tfogo_checklinkname0,with_naive_outbound,with_conntrack ./tools/udpprobe/ "$env:APPDATA\RescueBoat\RescueBoat\data\current-config.json"
```

Конфиг читается в память. Исходный файл не меняется. Перед запуском удаляются
`inbounds`, `experimental`, `route.rules`, `route.rule_set` и `dns.rules`.
Журнал sing-box отключается. Остальные настройки сохраняются. Конфиги с
`endpoints` или `services` отклоняются: эти компоненты могут создавать сетевые
интерфейсы и другие службы при запуске. Также отклоняется старый выход
WireGuard с `system_interface: true`. Утилита не включает системный прокси
и не создаёт TUN.

В выводе — тег в кавычках, результат UDP и результат TCP. Адреса и исходные
ошибки не печатаются: они могут содержать секреты. «Нет ответа» означает также
ошибку открытия соединения, записи или некорректный ответ. HTTP-проверка
использует `http://cp.cloudflare.com/`, как проба по умолчанию в ядре.

Успешная UDP-проба означает корректный DNS-ответ хотя бы от одной из двух целей:
`1.1.1.1:53` и `8.8.8.8:53`. NXDOMAIN тоже подтверждает работу UDP. Проверка
показывает доступность DNS через выход; сервер может отдельно ограничивать
другие UDP-порты.

Код завершения 1 означает ошибку чтения конфига или запуска. Результаты сетевых
проверок выводятся по каждому выходу и не меняют код завершения.
